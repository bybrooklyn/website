I have two machines that matter: the desktop I work on, and a server that sits at home and runs everything that should stay on. Here is how both are set up, and why.

## How I got here

The desktop went Ubuntu, then Debian, then Bazzite, then CachyOS, and CachyOS is the one I kept. It's Arch with less upkeep: it has the AUR, its packages and kernel are built for speed, and games work.

The server started on Ubuntu Server 24 and is now on Fedora Server.

I really hate Ubuntu and its stability and random issues.

## Why I self-host

- **I like owning my stuff.** My media, my code and my data, on hardware I own.
- **It's fun, and I learn from it.** Most of what I know about networks I learned by breaking this one.
- **It's cheaper.** Subscriptions add up. A server pays for itself.
- **I don't trust big platforms** to keep things around or keep them good.

Also, I pirate, and I'm proud of it.

## The desktop


### What boots

Limine is the boot loader. Plasma's login screen comes up, and then KDE Plasma on Wayland.

### Where things live

One Btrfs filesystem, split into subvolumes for the system, home, logs and caches. Snapper takes snapshots, and they show up in the boot menu, so I can undo a bad update by booting into the one before it.

## The server

Everything on it runs in Docker. Each service is a stack, which is a compose file, and I manage them in Portainer.

About thirty containers.

Anything private isn't exposed to the internet. I reach it over Tailscale, which puts my devices on the same network as the server wherever they are.

### The annoying part

My ISP blocks inbound connections on ports 80 and 443, which are the two a web server needs. So:

- Cloudflare is told, with an origin rule, to connect on a different port, one that is allowed in. Visitors use the normal address.
- Certificates can't be issued the usual way, because that check arrives on port 80. So the proxy proves ownership through DNS instead, and gets one wildcard certificate per domain.

## The *arr stack

Sonarr for shows, Radarr for films, Lidarr for music, LazyLibrarian for books, Prowlarr feeding all of them indexers, SABnzbd doing the downloading, and Seerr on top so people can ask for things.

Setting this up was a repetitive pain in the ass. Every one of these apps wants the same things typed into it again: the same folders, the same download client, the same API keys copied out of one tab and pasted into another, and then its own quality profiles on top. Do it for one and you get to do it again for all the others.

It doesn't stay set up, either. An indexer dies, a path changes, an update moves a setting, and you're back clicking through settings pages that all look almost the same. It works, and I'd still do it, but it is not a one-evening job.

## If you want to do this

1. Start with one service you will actually use. Jellyfin is a good first one.
2. Put a reverse proxy in front from day one. Adding it later means changing every address you've already given out.
3. Use Tailscale, or something like it, for anything only you need. Not everything has to be public.
4. Keep your compose files somewhere you can find them again. When you rebuild, they are what you rebuild from.
5. Check whether your ISP blocks ports before you plan around them.
6. Don't use Ubuntu.
